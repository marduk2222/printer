# 綠界 B2C 電子發票 - 一般開立發票 API

## 一、API 基本資訊

### 服務說明
- **功能**: 適用於即時開立發票
- **處理流程**: 綠界收到營業人(特店)傳送參數後進行開立，加值中心於 48 小時內協助上傳財政部

### API 介接網址
| 環境 | URL |
|------|-----|
| 測試環境 | `https://einvoice-stage.ecpay.com.tw/B2CInvoice/Issue` |
| 正式環境 | `https://einvoice.ecpay.com.tw/B2CInvoice/Issue` |

### HTTPS 傳輸協定
- **Content Type**: `application/json`
- **HTTP Method**: `POST`

---

## 二、特店傳入參數（JSON 格式）

### 根層參數

| 參數名稱 | 型別 | 長度 | 必填 | 說明 |
|---------|------|------|------|------|
| `PlatformID` | String | 10 | 否 | 特約合作平台商代號。僅限與綠界簽約的指定平台商使用；一般廠商請留空。平台商需填入已綁定的子廠商MerchantID |
| `MerchantID` | String | 10 | **是** | 特店編號 |
| `RqHeader` | Object | - | **是** | 傳入資料標頭 |
| `RqHeader.Timestamp` | Number | - | **是** | 傳入時間（Unix TimeStamp，GMT+8）。驗證時間區間為10分鐘內有效；超過則訂單無法建立 |
| `Data` | String | - | **是** | 加密資料（AES加密的JSON字串） |

**注意事項**:
- 合作特店須進行主機「時間校正」，避免時差導致 API 無法正常運作
- 參考資料: http://www.epochconverter.com/

## 三、Data 參數說明（加密前的 JSON 格式）

### 商家基本資訊

| 參數名稱 | 型別 | 長度 | 必填 | 說明 |
|---------|------|------|------|------|
| `MerchantID` | String | 10 | **是** | 特店編號 |
| `RelateNumber` | String | 50 | **是** | 特店自訂編號。需為唯一值，不可重複使用；不可使用特殊符號；大小寫英文視為相同 |
| `ChannelPartner` | String | 1 | 否 | 通路商編號：1=蝦皮，其餘數值忽略 |
| `CustomerID` | String | 20 | 否 | 客戶編號。格式為英文、數字、下底線等字元 |
| `ProductServiceID` | String | 10 | 否 | 產品服務別代號。需由英文字母（A-Z, a-z）和數字（0-9）組成，長度1-10字符。須於廠商後台啟用「B2C系統多組字軌」功能後才會生效 |

### 客戶資訊

| 參數名稱 | 型別 | 長度 | 必填 | 說明 |
|---------|------|------|------|------|
| `CustomerIdentifier` | String | 8 | 否 | 統一編號。格式為數字，固定8碼。建議使用「統一編號驗證API」進行格式驗證 |
| `CustomerName` | String | 60 | 條件必填 | 客戶名稱。當`Print=1`(列印)時為必填；格式為中、英文及數字。當統編有值時，請帶入相應營業人名稱 |
| `CustomerAddr` | String | 100 | 條件必填 | 客戶地址。當`Print=1`(列印)時為必填 |
| `CustomerPhone` | String | 20 | 條件必填 | 客戶手機號碼。當`CustomerEmail`為空時為必填；格式為數字 |
| `CustomerEmail` | String | 80 | 條件必填 | 客戶電子信箱。當`CustomerPhone`為空時為必填；需為有效Email格式，僅可填寫一組。測試環境勿帶入真實信箱，避免個資外洩 |

### 發票屬性

| 參數名稱 | 型別 | 長度 | 必填 | 說明 |
|---------|------|------|------|------|
| `ClearanceMark` | String | 1 | 條件必填 | 通關方式。當`TaxType=2`(零稅率)或`9`(混合)時為必填：1=非經海關出口，2=經海關出口 |
| `Print` | String | 1 | **是** | 列印註記：0=不列印，1=要列印。表示此張發票之後會被廠商自行印出紙本 |
| `Donation` | String | 1 | **是** | 捐贈註記：0=不捐贈，1=要捐贈 |
| `LoveCode` | String | 7 | 條件必填 | 捐贈碼。當`Donation=1`時為必填；格式為阿拉伯數字，3-7碼，首位可為零。建議先呼叫「捐贈碼驗證API」檢核 |
| `CarrierType` | String | 1 | 否 | 載具類別：空字串=無載具，1=綠界電子發票載具，2=自然人憑證號碼，3=手機條碼載具，4=悠遊卡，5=一卡通 |
| `CarrierNum` | String | 64 | 條件必填 | 載具編號。規則如下：<br>- `CarrierType=""`：帶空字串<br>- `CarrierType=1`：帶空字串，系統自動填入客戶Email或手機號碼<br>- `CarrierType=2`：固定16碼（2碼大寫英文+14碼數字）<br>- `CarrierType=3`：固定8碼（首碼為`/`，其餘7碼由0-9、A-Z、+、-、.組成）<br>- `CarrierType=4或5`：帶實體卡片的隱碼ID，不會檢核 |
| `CarrierNum2` | String | 64 | 條件必填 | 第二載具編號。當`CarrierType=4或5`時為必填，帶入卡片顯碼ID供發票查詢識別用 |

**Print 與 Donation 組合規則**:
- 捐贈發票：`Donation=1`時，`Print=0`，`CustomerIdentifier`必須為空
- 統編發票：`CustomerIdentifier`有值時，`Donation=0`
- 列印規則：
  - `CarrierType`為空：`Print`只能是1
  - `CarrierType=1或2`：`Print`只能是0
  - `CarrierType=3`：`Print`可為0或1

### 課稅資訊

| 參數名稱 | 型別 | 長度 | 必填 | 說明 |
|---------|------|------|------|------|
| `TaxType` | String | 1 | **是** | 課稅類別。字軌類別InvType=07時：1=應稅、2=零稅率、3=免稅、9=混合；InvType=08時：3=免稅、4=應稅(特種稅率) |
| `ZeroTaxRateReason` | String | 2 | 條件必填 | 零稅率原因。自115年1月1日起，當`TaxType=2或9`時為必填或廠商後台須設定，否則開立失敗。值列表：71-79分別代表第一~九款零稅率原因 |
| `SpecialTaxType` | Number | - | 條件必填 | 特種稅額類別。`TaxType=1/2/9`時自動帶0；`TaxType=3`時必填帶8；`TaxType=4`時必填帶1-8（分別代表不同特種稅率如酒家25%、夜總會15%等） |

**零稅率原因代碼表**:

| 代碼 | 說明 |
|------|------|
| 71 | 第一款 外銷貨物 |
| 72 | 第二款 與外銷有關之勞務，或在國內提供而在國外使用之勞務 |
| 73 | 第三款 依法設立之免稅商店銷售與過境或出境旅客之貨物 |
| 74 | 第四款 銷售與保稅區營業人供營運之貨物或勞務 |
| 75 | 第五款 國際間之運輸 |
| 76 | 第六款 國際運輸用之船舶、航空器及遠洋漁船 |
| 77 | 第七款 銷售與國際運輸用之船舶、航空器及遠洋漁船所使用之貨物或修繕勞務 |
| 78 | 第八款 保稅區營業人銷售與課稅區營業人未輸往課稅區而直接出口之貨物 |
| 79 | 第九款 保稅區營業人銷售與課稅區營業人存入自由港區事業或海關管理之保稅倉庫、物流中心以供外銷之貨物 |

### 金額資訊

| 參數名稱 | 型別 | 長度 | 必填 | 說明 |
|---------|------|------|------|------|
| `SalesAmount` | Number | 12 | **是** | 發票總金額(含稅)。帶整數，支援至12位，不可有小數點；僅限新台幣 |
| `TaxAmount` | Number | 11 | 否 | 稅額合計。帶整數，最多11位。按電子發票實施作業要點計算，若自行帶入，差距不得超過1元。非必填，未填由綠界代為計算。特種稅額發票請帶0 |
| `InvoiceRemark` | String | 200 | 否 | 發票備註 |

**稅額計算方式**:
- 一般發票(非混稅、非特種): `(發票金額 / 1.05) * 0.05` 並四捨五入至整數
- 混稅發票: `(應稅品項小計總和 / 1.05) * 0.05` 並四捨五入至整數

### 商品資訊

| 參數名稱 | 型別 | 長度 | 必填 | 說明 |
|---------|------|------|------|------|
| `Items` | Array[Object] | - | **是** | 商品陣列，可多筆，最多支援999項 |
| `Items[].ItemSeq` | Int | - | **是** | 商品序號。帶入1~999整數 |
| `Items[].ItemName` | String | 500 | **是** | 商品名稱 |
| `Items[].ItemCount` | Number | - | **是** | 商品數量。支援整數8位，小數7位 |
| `Items[].ItemWord` | String | 6 | **是** | 商品單位 |
| `Items[].ItemPrice` | Number | - | **是** | 商品單價。支援整數10位，小數7位。若vat=0(未稅)帶未稅金額；vat=1(含稅)帶含稅金額 |
| `Items[].ItemTaxType` | String | 1 | 條件必填 | 商品課稅別。當`TaxType=9`(混稅)時為必填：1=應稅，2=零稅率，3=免稅 |
| `Items[].ItemAmount` | Number | - | **是** | 商品合計。支援整數12位，小數7位；為含稅小計金額；所有ItemAmount加總後四捨五入=SalesAmount |
| `Items[].ItemRemark` | String | 120 | 否 | 商品備註 |

**商品金額計算規則**:
- 當`vat=1`且`TaxType=1`時: `ItemPrice(含稅) * ItemCount = ItemAmount(含稅)`
  - 例: `500 * 5 = 2500`
- 當`vat=0`且`TaxType=1`(稅率5%)時: `ItemPrice(未稅) * ItemCount * 1.05 = ItemAmount(含稅)`
  - 例: `500 * 5 * 1.05 = 2625`

**混稅發票商品課稅類別限制**:
- 免稅和零稅率發票不能同時開立
- 商品課稅類別只能為: (應稅+免稅) 或 (應稅+零稅率)

### 字軌資訊

| 參數名稱 | 型別 | 長度 | 必填 | 說明 |
|---------|------|------|------|------|
| `InvType` | String | 2 | **是** | 字軌類別：07=一般稅額，08=特種稅額 |
| `vat` | String | 1 | 否 | 商品單價是否含稅。預設為含稅(1)：1=含稅，0=未稅 |

## 九、加密方法說明

**處理步驟**:
1. 將 Data 參數的 JSON 字串進行 **URLencode**
2. 使用 **AES 加密**（詳見官方文件「參數加密方式說明」）
3. 回傳資料解密流程相反：先 **AES 解密**，再 **URLdecode**

參考文件: https://developers.ecpay.com.tw/?p=7958

## 十、發票使用情境詳細說明

### 情境一：捐贈發票
- 用戶選擇捐贈 `Donation=1`
- `Print=0`（捐贈發票不需列印）
- `CustomerIdentifier`：必須為空，捐贈時不能指定統編
- `CarrierType`：若不為空且`Donation=1`，發票開立當下存在載具內，消費者後續捐贈成功，最終狀態為捐贈成功

### 情境二：統一編號發票
- 用戶提供 `CustomerIdentifier`
- `Donation`：只能是0（指定統編時不能捐贈）
- 可以存載具 `CarrierType`
- `Print` 規則：
  - `CarrierType`為空：`Print`只能是1
  - `CarrierType=1或2`：`Print`只能是0
  - `CarrierType=3`：`Print`可為0或1

### 情境三：選擇存放載具
- 若 `CustomerIdentifier` 有值且需列印 `Print=1`：`CarrierType` 只能選3(手機條碼)
- 若不需列印 `Print=0` 且提供統編：`CarrierType` 不可為空

## 十一、特殊業務案例

### 超商 KIOSK 事務機列印注意事項
（需向業務申請開通）

1. **列印消費發票 (ibon)**
   - 參數組合: `Print=1, CarrierType="", CustomerIdentifier="", Donation=0`
   - 限列印一次（之後中獎也無法再列印）

2. **列印中獎發票 (ibon, FamiPort)**
   - 參數組合: `Print=0, CarrierType=1, CustomerIdentifier="", Donation=0`
   - 限列印一次

3. **折讓後發票金額為 0 元**
   - 不可列印

## 十三、重要注意事項彙整

1. **時間驗證**: 驗證時間區間為10分鐘內有效
2. **RelateNumber**: 必須唯一，不可重複使用；大小寫英文視為相同
3. **Email 驗證**: 測試環境勿帶入真實電子信箱；格式需符合正規表達式；測試環境不提供發信測試
4. **載具與列印**: 當列印且含統編時，若需載具只能用手機條碼(CarrierType=3)
5. **手機條碼**: 先呼叫手機條碼驗證API檢核，避免歸戶失敗
6. **統編驗證**: 使用統一編號驗證API進行格式驗證
7. **捐贈碼**: 先呼叫捐贈碼驗證API檢核，推薦168001
8. **悠遊卡/一卡通**: 查詢發票API因資安考量不會回傳隱碼ID
