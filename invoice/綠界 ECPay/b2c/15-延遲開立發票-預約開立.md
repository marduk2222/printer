# 綠界 B2C 電子發票 延遲開立發票 API

## 服務概述

本 API 允許營業人（特店）預先將開立發票參數傳送至綠界系統暫存，待延遲開立時間到達時，系統自動開立電子發票並上傳財政部，同時通知消費者。

## 應用場景

### 場景一：預約開立發票
特店預先傳送發票參數至綠界，系統於指定時間自動開立發票。

### 場景二：觸發開立發票
特店預先傳送參數，等待確認後再由特店觸發開立流程。

## API介接網址

| 環境 | 網址 |
|------|------|
| 測試環境 | `https://einvoice-stage.ecpay.com.tw/B2CInvoice/DelayIssue` |
| 正式環境 | `https://einvoice.ecpay.com.tw/B2CInvoice/DelayIssue` |

## HTTPS傳輸協定

- **Content Type**：application/json
- **HTTP Method**：POST

## 防火牆設定需求

如使用延遲開立發票 API，需放行以下位址：
- 正式環境：postgate.ecpay.com.tw TCP 443
- 測試環境：postgate-stage.ecpay.com.tw TCP 443

| ProductServiceID | String | 10 | 否 | 產品服務別代號，由英文及數字組成，長度 1-10 字符，需啟用 B2C 多組字軌功能 |

| 欄位 | 型別 | 長度 | 必填 | 說明 |
|------|------|------|------|------|
| CustomerIdentifier | String | 8 | 條件 | 統一編號，格式為 8 碼數字，需符合財政部檢核邏輯 |
| CustomerName | String | 60 | 條件 | 客戶名稱，格式為中、英文及數字。列印時 [Print]=1 為必填 |

|------|------|------|------|------|
| CarrierType | String | 1 | 否 | 載具類別：空字串=無載具；1=綠界電子發票載具；2=自然人憑證；3=手機條碼；4=悠遊卡；5=一卡通 |

## 使用情境說明

### 情境一：捐贈發票

- 用戶選擇捐贈 [Donation]=1
  - 列印 [Print]=0：捐贈發票不需列印
  - 統一編號 [CustomerIdentifier]：必須為空
  - 載具 [CarrierType]：若非空且 Donation=1，代表發票存在載具內，消費者後續捐贈成功時最終狀態為捐贈成功

### 情境二：統一編號發票

- 用戶提供統一編號 [CustomerIdentifier]
  - 捐贈 [Donation] 只能是 0
  - 可存載具 [CarrierType]
  - 列印 [Print] 依載具類別而定：
    - 載具為空時：Print=1（要列印）
    - 載具為 1 或 2 時：Print=0（不列印）
    - 載具為 3 時：Print=0 或 1 皆可

### 情境三：選擇存放載具

- 用戶選擇特定載具 [CarrierType]
  - 若有統一編號且需列印 [Print=1]：載具只能選 3（手機條碼）
  - 若不需列印 [Print=0] 且有統一編號：載具不可為空

## 商品金額計算規則

### ItemAmount 需統一為含稅金額，規則如下：

**規則 1**：當 vat=1 且 TaxType=1
```
ItemPrice(含稅) × ItemCount = ItemAmount(含稅)
例：500 × 5 = 2500
```

**規則 2**：當 vat=0 且 TaxType=1（稅率 5%）
```
ItemPrice(未稅) × ItemCount × 1.05 = ItemAmount(含稅)
例：500 × 5 × 1.05 = 2625
```

### 混稅發票稅額計算（TaxType=9）

```
(應稅品項小計總和 / 1.05) × 0.05 並四捨五入至整數
```

### 一般發票稅額計算（非混稅、非特種）

```
(發票金額 / 1.05) × 0.05 並四捨五入至整數
```

## 重要注意事項

### 時間驗證

- 驗證時間區間為 10 分鐘內有效，超過此時間訂單無法建立
- 合作特店須進行主機「時間校正」，避免主機時差導致 API 無法正常運作

### 延遲開立限制

- **開立當天 10 點後無法取消開立**
- 延遲開立時：DelayDay=7，代表 7 天後自動開立
- 觸發開立時：DelayDay=2，代表被觸發後過 2 天才會開立；若未被觸發則不會開立

### 列印相關規定

1. Print 參數意義為「註記發票將被廠商自行印出紙本」，並非指由綠界代為列印與寄送
2. 捐贈發票時需帶 Print=0
3. 超商 KIOSK 事務機列印規定：
   - 消費發票(ibon)：Print=1、CarrierType=""、CustomerIdentifier=""、Donation=0，只能列印一次
   - 中獎發票(ibon、FamiPort)：Print=0、CarrierType=1、CustomerIdentifier=""、Donation=0，只能列印一次
   - 折讓後發票金額為 0 元，不可列印

### 統一編號驗證

- 格式為 8 碼數字
- 需符合財政部最新的檢核邏輯
- 不符檢核邏輯時開立發票將失敗

### 手機條碼載具

- CarrierNum 固定長度 8 碼：首碼為【/】，其餘 7 碼由數字【0-9】、大寫英文【A-Z】、特殊符號【+】【-】【.】組成
- 建議先呼叫手機條碼驗證 API 進行檢核，避免條碼有誤造成發票歸戶失敗
- 英文、數字、符號僅接受半形字元

### 自然人憑證

- CarrierNum 格式：固定 16 碼，2 碼大寫英文字母+14 碼數字

### 悠遊卡與一卡通

- CarrierNum 為隱碼 id（內碼），需透過讀卡機取得
- CarrierNum2 為顯碼 id（外碼），為卡片上外顯號碼
- 查詢發票 API 不會因資安考量回傳隱碼 id
- 英文、數字、符號僅接受半形字元

### 客戶聯絡方式

- 客戶手機 [CustomerPhone] 和客戶電子信箱 [CustomerEmail] 至少需填一個
- 測試環境勿帶入真實電子信箱，避免個資外洩
- 測試環境僅驗規則，不提供發信測試
- Email 格式檢核使用複雜正規表達式

### 捐贈碼規定

- 推薦捐贈碼：168001（OMG 關懷社會愛心基金會）
- 使用捐贈碼前應先呼叫捐贈碼驗證 API 檢核
- 格式為阿拉伯數字，最少 3 碼、最多 7 碼，首位可為零

### 零稅率原因（自 115 年 1 月 1 日起）

當 TaxType=2 或 9 時，需填寫 ZeroTaxRateReason：
- 71：外銷貨物
- 72：與外銷有關之勞務
- 73：免稅商店銷售與過境出境旅客之貨物
- 74：銷售與保稅區營業人
- 75：國際間運輸
- 76：國際運輸用之船舶、航空器及遠洋漁船
- 77：銷售與國際運輸用船舶、航空器之貨物或修繕勞務
- 78：保稅區營業人銷售課稅區營業人直接出口之貨物
- 79：保稅區營業人銷售課稅區營業人之外銷貨物

### 混稅發票商品課稅別

- TaxType=9 時，免稅和零稅率發票不能同時開立
- 商品課稅別 [ItemTaxType] 只能為以下組合：
  - 應稅+免稅
  - 應稅+零稅率

### RelateNumber 規定

- 需為唯一值，不可重複使用
- 不可使用特殊符號
- 大小寫英文視為相同（例：123abc456=123ABC456）

### 產品服務別代號 (ProductServiceID)

- 需啟用「B2C 系統多組字軌」功能
- 由英文字母 (A-Z、a-z) 和數字 (0-9) 組成
- 長度 1-10 字符
- 需在廠商後台「字軌分類管理」新增商品/服務別分類
- 在「字軌與配號設定」新增對應字軌配號
