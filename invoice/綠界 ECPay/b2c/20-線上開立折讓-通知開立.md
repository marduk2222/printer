# 綠界 B2C 電子發票 - 線上開立折讓（通知開立）API

## 功能概述

營業人可使用此功能將折讓開立參數傳送至綠界，由綠界暫存折讓資料，並發送折讓同意通知信給消費者。待消費者點選信件中的同意折讓後，綠界即時通知營業人折讓單已開立並回傳折讓單號碼。隔日將折讓資料上傳至財政部電子發票整合服務平台，並通知消費者。

## API 介接網址

- **測試環境**：https://einvoice-stage.ecpay.com.tw/B2CInvoice/AllowanceByCollegiate
- **正式環境**：https://einvoice.ecpay.com.tw/B2CInvoice/AllowanceByCollegiate

## HTTPS 傳輸協定

```
Content Type: application/json
HTTP Method: POST
```

## 特店傳入參數（JSON 格式）

| 參數名稱 | 資料型別 | 長度 | 必填 | 說明 |
|---------|---------|------|------|------|
| PlatformID | String | 10 | 否 | 特約合作平台商代號。一般廠商請保留為空 |
| MerchantID | String | 10 | **是** | 特店編號 |
| RqHeader | Object | - | **是** | 傳入資料 |
| Data | String | - | **是** | 加密資料（加密方法需先進行 urlencode 後再進行 AES 加密） |

### RqHeader 物件

| 參數名稱 | 資料型別 | 必填 | 說明 |
|---------|---------|------|------|
| Timestamp | Number | **是** | 傳入時間，轉換為時間戳(GMT+8)。驗證時間區間為 10 分鐘內有效 |

### 特店傳入參數範例

```json
{
    "MerchantID": "2000132",
    "RqHeader": {
        "Timestamp": 1525168923
    },
    "Data": "加密資料"
}
```

## Data 參數說明（JSON 格式）

須先將 JSON 字串進行 urlencode 後再進行 AES 加密

| 參數名稱 | 資料型別 | 長度 | 必填 | 說明 |
|---------|---------|------|------|------|
| MerchantID | String | 10 | **是** | 特店編號 |
| InvoiceNo | String | 10 | **是** | 發票號碼（長度固定為10碼） |
| InvoiceDate | String | 10 | **是** | 發票開立日期，格式為「yyyy-MM-dd」或「yyyy/MM/dd」 |
| AllowanceNotify | String | 1 | **是** | 通知類別，固定填 E（電子郵件）。開立折讓後寄送相關發票折讓資訊通知消費者 |
| CustomerName | String | 60 | 否 | 客戶名稱，格式為中、英文及數字等 |
| NotifyMail | String | 100 | 否 | 通知電子信箱，需為有效的 Email 格式。可帶入多組 Email，以分號區隔（例：aa@aa.aa;bb@bb.bb） |
| AllowanceAmount | Number | - | **是** | 折讓單總金額(含稅)，支援整數12位。應大於0元 |
| Reason | String | 50 | 否 | 折讓原因 |
| Items | Array[Object] | - | **是** | 商品陣列 |
| ReturnURL | String | 200 | 否 | 消費者同意後回傳網址。當消費者點選同意後，綠界會將成功的結果參數以幕後(Server POST)回傳 |

### AllowanceAmount 注意事項

折讓單總金額應大於 0 元：
1. 若此張發票未折讓過，應小於或等於原發票總金額
2. 若此張發票已折讓過，應小於或等於折讓剩餘金額
3. 折讓單總金額設 0 元不被允許

### Items 物件（商品陣列）

| 參數名稱 | 資料型別 | 長度 | 必填 | 說明 |
|---------|---------|------|------|------|
| ItemSeq | Int | - | 否 | 商品序號 |
| ItemName | String | 500 | **是** | 商品名稱，不可為空字串 |
| ItemCount | Number | - | **是** | 商品數量，支援整數8位，小數7位 |
| ItemWord | String | 6 | **是** | 商品單位 |
| ItemPrice | Number | - | **是** | 商品單價，支援整數10位，小數7位 |
| ItemTaxType | String | 1 | 否 | 商品課稅別（1：應稅；2：零稅率；3：免稅）。當課稅類別[TaxType]=9時，此欄位不可為空 |
| ItemAmount | Number | - | **是** | 商品合計（含稅小計金額），支援整數12位，小數7位 |

### ItemTaxType 注意事項

預設為空字串。課稅類別為混合稅率時，需含二筆或以上的商品課稅別[ItemTaxType]，且至少需有一筆商品課稅別為應稅及至少需有一筆商品課稅別為免稅或零稅率。混稅發票只能：
1. 應稅+免稅
2. 應稅+零稅率

免稅和零稅率發票不能同時開立。

### ItemAmount 注意事項

- 假設 A = 商品單價[ItemPrice] × 商品數量[ItemCount]，則 A 與商品合計[ItemAmount]允許1元以內的誤差
- 各商品之商品合計[ItemAmount]加總需等於折讓單總金額[AllowanceAmount]
- 依營業稅電子資料申報繳稅作業要點，電子發票銷貨退回、進貨退出或折讓證明單之「金額(不含稅之進貨額)」及「營業稅額」欄位須為整數，建議此欄位請帶入整數

```json
{
    "MerchantID": 2000132,

        {
            "ItemSeq": 1,

            "ItemCount": 1,
```

| 參數名稱 | 資料型別 | 長度 | 說明 |
|---------|---------|------|------|
| PlatformID | String | 10 | 特約合作平台商代號 |
| MerchantID | String | 10 | 特店編號 |
| RpHeader | Object | - | 回傳資料 |
| TransCode | Int | - | 回傳代碼，1 代表 API 傳輸資料接收成功，實際執行結果狀態請參考 RtnCode |

### RpHeader 物件

| 參數名稱 | 資料型別 | 說明 |
|---------|---------|------|

## Data 參數說明（JSON 格式）

須先將 Data 進行 AES 解密後再做 urldecode

| 參數名稱 | 資料型別 | 長度 | 說明 |
|---------|---------|------|------|
| RtnCode | Int | - | 回應代碼。1 代表 API 執行成功，其餘代碼均為失敗。**成功代表 API 呼叫成功，需消費者同意後才算開立折讓單成功** |
| RtnMsg | String | 200 | 回應訊息 |
| IA_Allow_No | String | 16 | 折讓單號。建立成功會回傳折讓單號；建立失敗則回傳空值 |
| IA_Invoice_No | String | 10 | 發票號碼。建立成功會回傳當初開立的發票號碼；建立失敗則回傳空值 |
| IA_TempDate | String | 20 | 線上折讓時間。建立成功會回傳線上折讓時間，回傳格式為「yyyy-MM-dd HH:mm:ss」；建立失敗則回傳空值 |
| IA_TempExpireDate | String | 20 | 線上折讓同意到期日。建立成功會回傳線上折讓同意到期日，回傳格式為「yyyy-MM-dd HH:mm:ss」；建立失敗則回傳空值 |
| IA_Remain_Allowance_Amt | Int | - | 折讓剩餘金額。建立成功會回傳開立折讓後剩餘金額；建立失敗則回傳空值 |

### Data 參數範例

```json
{
    "RtnCode": 1,
    "RtnMsg": "折讓單資料新增成功",
    "IA_Allow_No": "1909181313013546",
    "IA_Invoice_No": "UV11100019",
    "IA_TempDate": "2019-09-18 13:13:23",
    "IA_TempExpireDate": "2019-09-21 13:13:23",
    "IA_Remain_Allowance_Amt": 0
}
```

## ReturnURL 通知

### HTTPS 傳輸協定

```
Accept: text/html
Content Type: application/x-www-form-urlencoded
HTTP Method: POST
```

### ReturnURL 綠界回傳參數說明

| 參數名稱 | 資料型別 | 長度 | 說明 |
|---------|---------|------|------|
| RtnCode | Int | - | 回應代碼。1 代表客戶折讓成功，只有折讓成功才會收到通知。如果超過 72 小時仍未收到通知，請透過查詢折讓明細 API 進行確認 |
| RtnMsg | String | 200 | 回應訊息 |
| IA_Allow_No | String | 16 | 折讓單號。開立成功會回傳折讓單號 |
| IA_Invoice_No | String | 10 | 發票號碼。開立成功會回傳當初開立的發票號碼 |
| IA_Date | String | 20 | 折讓時間。開立成功會回傳開立折讓時間，回傳格式為「yyyy-MM-dd HH:mm:ss」 |
| IIS_Remain_Allowance_Amt | Int | - | 折讓剩餘金額。開立成功會回傳開立折讓後剩餘金額，支援整數 12 位 |
| CheckMacValue | String | - | 檢查碼，綠界會將以上參數使用檢查碼機制運算後回傳此參數以確保資料在傳輸過程沒有被竄改 |

### ReturnURL 回傳範例

```
RtnCode=1&RtnMsg=&IA_Allow_No=1909181313013546&IA_Invoice_No=UV11100019&IA_Date=2019-09-18 13:13:23&IIS_Remain_Allowance_Amt=0&CheckMacValue=72F8C0BB157D97E68FCAF5E79E8E142D6B346BEEB756288BC668A5AA2C34980E
```

## CheckMacValue 檢查碼計算規則

綠界會將參數 RtnCode、RtnMsg、IA_Allow_No、IA_Invoice_No、IA_Date 與 IIS_Remain_Allowance_Amt 使用檢查碼機制運算後回傳此參數 [CheckMacValue]，以確保資料在傳輸過程沒有被竄改。廠商如果對於資料安全有疑慮，可以自行利用檢查碼機制將收到的參數產生檢查碼後與此參數 [CheckMacValue] 比對是否一致。

詳細檢查碼機制說明請參考：https://developers.ecpay.com.tw/?p=38242

## 注意事項

1. **消費者同意確認**：送出後，還需買受人 Email 確認折讓內容，並點擊確認驗證連結（72 小時有效）。點擊驗證連結當下銷貨折讓才開立。買受人未點擊驗證連結前，可隨時取消此筆折讓。

2. **紙本折讓單免除**：使用線上同意，無須再郵寄紙本折讓單給消費者簽名存檔。綠界系統會記錄買受人點擊確認同意連結的相關 log。

3. **測試環境限制**：測試環境(Stage)因資安考量不會寄發任何 Mail，請在正式環境(Prod)進行 Mail 寄送測試。

4. **ReturnURL 回應**：請在收到 Server 端折讓成功結果通知後，請正確回應 `1|OK` 給綠界。

5. **主機時間校正**：合作特店須進行主機「時間校正」，避免主機產生時差，導致 API 無法正常運作。
