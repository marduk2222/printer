# 綠界 B2C 電子發票 統一編號驗證 API

## 應用場景

特店系統可利用此 API 來驗證統一編號，並取得對應的公司名稱資訊。

## 重要注意事項

此 API 功能為驗證統一編號格式，並查詢開放資料及財政部 API 取得公司名稱。**查不到公司名稱不代表統一編號不存在**，例如公司福委會、部分政府機構及醫療機構可能無法查詢。應將本 API 作為輔助驗證工具，**僅當回應代碼是 1200125（統一編號格式錯誤）時才停止發票開立**。

---

## API 介接資訊

### 環境端點

| 環境 | URL |
|------|-----|
| 測試環境 | `https://einvoice-stage.ecpay.com.tw/B2CInvoice/GetCompanyNameByTaxID` |
| 正式環境 | `https://einvoice.ecpay.com.tw/B2CInvoice/GetCompanyNameByTaxID` |

### 傳輸協定

- **Content Type**：application/json
- **HTTP Method**：POST

---

## 請求參數 (JSON 格式)

### 頂層參數

| 參數名稱 | 型別 | 長度 | 必填 | 說明 |
|---------|------|------|------|------|
| PlatformID | String | 10 | 否 | 特約合作平台商代號，一般廠商保留為空 |
| MerchantID | String | 10 | 是 | 特店編號 |
| RqHeader | Object | - | 是 | 傳入資料標頭 |
| Data | String | - | 是 | 加密資料（AES加密的JSON格式） |

### RqHeader 參數

| 參數名稱 | 型別 | 說明 |
|---------|------|------|
| Timestamp | Number | 傳輸時間的 Unix TimeStamp (GMT+8)，驗證時間區間為 10 分鐘內有效 |

### Data 參數內容 (加密前的 JSON)

先進行 URL encode，再進行 AES 加密。

| 參數名稱 | 型別 | 長度 | 必填 | 說明 |
|---------|------|------|------|------|
| MerchantID | String | 10 | 是 | 特店編號 |
| UnifiedBusinessNo | String | 8 | 是 | 統一編號（僅限數字） |

### 請求範例

```json
{
    "MerchantID": "2000132",
    "RqHeader": {
        "Timestamp": 1525168923
    },
    "Data": "加密資料"
}
```

**Data 加密前內容範例**：
```json
{
    "MerchantID": "2000132",
    "UnifiedBusinessNo": "97025978"
}
```

## 回傳參數 (JSON 格式)

### 頂層參數

| 參數名稱 | 型別 | 說明 |
|---------|------|------|
| PlatformID | String | 特約合作平台商代號 |
| MerchantID | String | 特店編號 |
| RpHeader | Object | 回傳資料標頭 |
| TransCode | Integer | 傳輸代碼（1 表示 API 資料接收成功） |
| TransMsg | String | 傳輸訊息 |
| Data | String | 加密資料（AES加密的JSON格式） |

### RpHeader 參數

| 參數名稱 | 型別 | 說明 |
|---------|------|------|
| Timestamp | Number | 回傳時間的 Unix TimeStamp (GMT+8) |

### Data 參數內容 (解密後的 JSON)

先進行 AES 解密，再進行 URL decode。

| 參數名稱 | 型別 | 長度 | 說明 |
|---------|------|------|------|
| RtnCode | Integer | - | 回應代碼 |
| RtnMsg | String | 200 | 回應訊息 |
| CompanyName | String | 60 | 公司名稱（僅在格式正確且查詢成功時回傳） |

### 回傳範例

```json
{
    "MerchantID": "2000132",
    "RpHeader": {
        "Timestamp": 1525169058
    },
    "TransCode": 1,
    "TransMsg": "",
    "Data": "加密資料"
}
```

**Data 解密後內容範例**：
```json
{
    "RtnCode": 1,
    "RtnMsg": "查詢名稱成功",
    "CompanyName": "綠界科技股份有限公司"
}
```

## 回應代碼對照表

| 回應代碼 | 回應訊息 | 說明 | 建議動作 |
|---------|---------|------|---------|
| 1 | （公司名稱） | 統一編號格式正確，並在資料庫成功比對到資料 | 可繼續完成發票開立 |
| 1200125 | 統一編號檢查碼驗證失敗，請再確認 | 輸入值不符合統一編號檢查碼邏輯規則 | 停止開立發票，檢核統一編號是否正確 |
| 2027000 | 統一編號格式錯誤，請重新確認 | 輸入值長度不符合 8 碼規範 | 停止開立發票，檢查統一編號長度 |
| 7 | 查無資料 | 該統一編號在所有公開資料來源中均查無對應資料 | 可繼續完成發票開立（部分組織機構無公開資料） |
| 9000001 | 呼叫財政部 API 失敗 | 因網路或外部系統問題，無法完成財政部 API 呼叫 | 可繼續完成發票開立 |

## 加密方法說明

參照文件：[參數加密方式說明](https://developers.ecpay.com.tw/?p=7958)

請求資料的 Data 參數加密流程：
1. 將 JSON 資料進行 URL encode
2. 使用 AES 加密（綠界提供的加密金鑰）

回傳資料的 Data 參數解密流程：
1. 使用 AES 解密（綠界提供的解密金鑰）
2. 將解密後的資料進行 URL decode 得到 JSON
