# 綠界 B2C 電子發票 編輯延遲開立發票 API

## 功能概述

營業人(特店)可使用此功能先將延遲開立發票(預約開立發票)進行修改。

## 使用流程說明

可針對延遲開立的發票參數內容進行修改，請帶入原延遲開立取得的 Tsr 參數進行修改。

## API 介接網址

- **測試環境**：https://einvoice-stage.ecpay.com.tw/B2CInvoice/EditDelayIssue
- **正式環境**：https://einvoice.ecpay.com.tw/B2CInvoice/EditDelayIssue

## HTTPS 傳輸協定

- **Content Type**：application/json
- **HTTP Method**：POST

## 特店傳入參數(Json 格式)

### 必填參數

| 參數名稱 | 型別 | 長度 | 說明 |
|---------|------|------|------|
| **MerchantID** | String | 10 | 特店編號 (必填) |
| **RqHeader** | Object | - | 傳入資料 (必填) |
| **Timestamp** | Number | - | 傳入時間 (GMT+8)，Unix TimeStamp 格式 (必填) |
| **Data** | String | - | 加密過 JSON 格式的資料 (必填) |
| **PlatformID** | String | 10 | 特約合作平台商代號 (選填) |

### RqHeader 內容

```json
{
  "Timestamp": 1525168923
}
```

### 傳入參數範例

```json
{
  "MerchantID": "2000132",
  "RqHeader": {
    "Timestamp": 1525168923
  },
  "Data": "加密資料"
}
```

## 使用情境說明

### 使用情境一：捐贈發票

當用戶選擇捐贈發票 [Donation]=1

- 列印參數 [Print]=0：捐贈發票不需要列印
- 統一編號 [CustomerIdentifier]：必須為空
- 載具類別 [CarrierType]：當不為空字串且 [Donation]=1 時，代表發票存在載具內，消費者將其捐贈成功

### 使用情境二：統一編號發票

當用戶提供統一編號 [CustomerIdentifier]

- 捐贈參數 [Donation] 只能是 0
- 可以存載具 [CarrierType]
- 列印參數 [Print]：依載具類別而定
  - 載具類別為空：Print=1（要列印）
  - 載具類別為 1 或 2：Print=0（不列印）
  - 載具類別為 3：Print=0 或 1

### 使用情境三：選擇存放載具

當用戶選擇特定載具 [CarrierType]

- 若統一編號 [CustomerIdentifier] 有值且 Print=1：CarrierType 只能選擇 3（手機條碼載具）
- 若不需要列印 [Print=0] 且提供統一編號：載具不可為空

## 綠界回傳參數格式

- **Content Type**：application/json
- **HTTP Method**：POST

| 參數名稱 | 型別 | 長度 | 說明 |
|---------|------|------|------|
| **PlatformID** | String | 10 | 特約合作平台商代號 |
| **MerchantID** | String | 10 | 特店編號 |
| **RpHeader** | Object | - | 回傳資料 |
| **Timestamp** | Number | - | 回傳時間 (Unix timestamp GMT+8) |
| **TransCode** | Int | - | 回傳代碼 (1:接收成功) |
| **TransMsg** | String | 200 | 回傳訊息 |
| **Data** | String | - | 加密過 JSON 格式的資料 |

## Data 參數說明(Json 格式) - 回傳

請先將 Data 進行 AES 解密後再做 urldecode

| 參數名稱 | 型別 | 長度 | 說明 |
|---------|------|------|------|
| **RtnCode** | Int | - | 回應代碼 (1:成功，其餘為失敗) |
| **RtnMsg** | String | 200 | 回應訊息 |
| **OrderNumber** | String | 30 | 交易單號 (Tsr)；成功回傳交易單號，失敗回傳空值 |

  "RtnCode": 1,
  "RtnMsg": "修改發票成功",

## 重要注意事項

### 時間驗證

- 驗證時間區間為 10 分鐘內有效
- 超過驗證時間則此次訂單將無法建立
- 合作特店須進行主機「時間校正」，避免時差導致 API 無法運作

### 特店自訂編號(RelateNumber)

- 不得與已完成開立發票的特店自訂編號重複
- 與目前待開立中的發票的特店自訂編號重覆是允許的
- 誰先被觸發開立，則其餘相同特店自訂編號的發票就不會再被觸發
- 勿使用特殊符號
- 大小寫英文視為相同 (e.g. 123abc456=123ABC456)

### 列印(Print)參數注意事項

1. 此參數意義為註記這張發票之後會被廠商自行印出紙本
2. 當捐贈註記 [Donation]=1，此參數請帶 0
3. 當統一編號 [CustomerIdentifier] 有值時
   - 載具類別 [CarrierType] 為空值：Print=1
   - 載具類別 [CarrierType]=1 或 2：Print=0
   - 載具類別 [CarrierType]=3：Print=0 或 1

### 超商 KIOSK 事務機列印注意事項

1. 列印消費發票(ibon)
   - Print=1, CarrierType="", CustomerIdentifier="", Donation=0
   - 只能列印一次(之後中獎也無法再次列印)

2. 列印中獎發票(ibon, FamiPort)
   - Print=0, CarrierType=1, CustomerIdentifier="", Donation=0
   - 只能列印一次

3. 折讓後發票金額為 0 元，不可列印

### 載具編號(CarrierNum)

- **CarrierType=""**：請帶空字串
- **CarrierType=1**：請帶空字串，系統自動帶入客戶電子信箱或手機號碼(優先信箱)，綠界重新編碼產出
- **CarrierType=2**：固定 16 碼格式(2 碼大寫英文+14 碼數字)
- **CarrierType=3**：固定 8 碼(第 1 碼【/】+7 碼英數字或 +-. 符號)
- **CarrierType=4 或 5**：必填，帶入實體卡片的隱碼 id

### 載具編號(CarrierNum2)

- **CarrierType=4 或 5**：必填，帶入實體卡片的顯碼 id
- **CarrierType=1/2/3**：無須填入

### 商品金額計算規則

當 vat=1 且 TaxType=1：
```
ItemPrice(含稅) × ItemCount = ItemAmount(含稅)
例：500 × 5 = 2500
```

當 vat=0 且 TaxType=1(稅率 5%)：
```
ItemPrice(不含稅) × ItemCount × 1.05 = ItemAmount(含稅)
例：500 × 5 × 1.05 = 2625
```
