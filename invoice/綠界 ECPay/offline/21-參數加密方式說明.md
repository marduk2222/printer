# 參數加密方式說明

> 注意：原頁面為綠界開發者公開技術規格，WebFetch 拒絕逐字重現著作權內容，下列為技術規格擷取摘要。實作前請以官方原頁面為準。

## 核心加密參數

| 項目 | 規格 |
|------|------|
| 金鑰長度 | AES 加密強度設定為 128 bit |
| 加密模式 | CBC |
| 填充方式 | PKCS7 |
| IV 處理 | 綠界提供專用的 HashIV，與 HashKey 分開使用 |

## 加密流程順序 (Encryption)

1. **URLEncode 編碼** — 先將 JSON 字串資料進行網址編碼 (特殊字元編碼可為大寫或小寫)
2. **AES-128-CBC 加密** — 使用 HashKey 作為 Key、HashIV 作為 IV，PKCS7 padding 執行加密
3. **Base64 編碼** — 加密結果以 Base64 格式輸出，作為 Data 欄位送出

## 解密流程順序 (Decryption)

1. **Base64 解碼** — 還原加密的二進位資料
2. **AES-128-CBC 解密** — 使用相同的 HashKey 與 HashIV 解密
3. **URLDecode 解碼** — 將結果還原為原始 JSON 字串

## 實作範例呼叫方式

| 語言 | 常用函式 | 說明 |
|------|---------|------|
| C# | `AesManaged` | `System.Security.Cryptography` 命名空間 |
| PHP | `openssl_encrypt()` | 參數：資料、`'AES-128-CBC'`、Key、選項、IV |
| Java | `Cipher.getInstance("AES/CBC/PKCS5Padding")` | Java 的 PKCS5Padding 在 16-byte block 下與 PKCS7 結果相同 |
| Python | `PyCryptodome` 或 `cryptography` | `Cipher` 類別搭配 CBC 模式 |

## 測試金鑰範例

| 項目 | 值 |
|------|----|
| HashKey | `HwiqPsywG1hLQNuN` |
| HashIV | `YqITWD4TyKacYXpn` |

> 此為測試範例資訊。正式環境應取得對應的 MerchantID、HashKey 與 HashIV。

## 注意事項

- URLEncode 須在 AES 加密之前執行，AES 解密之後才執行 URLDecode。
- HashKey 與 HashIV 屬於敏感金鑰，不得寫死於前端程式碼。
- URLEncode 對照可參考附錄 [URLEncode 轉換表](./20-URLEncode轉換表.md)。
