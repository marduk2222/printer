# B2B 電子發票 API - 開立發票

## 應用場景

特店（營業人）傳送開立發票參數給綠界科技加值中心後，由綠界暫存相關資料。綠界於隔日開立發票後上傳至財政部電子發票整合服務平台，並根據設定通知交易相對人電子發票已開立。

## API 介接網址

| 環境 | URL |
|------|-----|
| 測試環境 | https://einvoice-stage.ecpay.com.tw/B2BInvoice/Issue |
| 正式環境 | https://einvoice.ecpay.com.tw/B2BInvoice/Issue |

## 特店 Request 參數說明（JSON 格式）

### 外層參數

| 欄位名稱 | 型別 | 長度 | 必填 | 說明 |
|---------|------|------|------|------|
| PlatformID | String | 10 | 否 | 特約合作平台商代號；一般廠商請放空值 |
| MerchantID | String | 10 | 是 | 特店編號 |
| RqHeader | Object | - | 是 | 傳入資料 |
| Data | String | - | 是 | 加密資料（加密過的 JSON 格式） |

### RqHeader 物件

| 欄位名稱 | 型別 | 必填 | 說明 |
|---------|------|------|------|
| Timestamp | Number | 是 | 傳入時間（Unix TimeStamp），驗證時間區間為 10 分鐘內有效 |

### Request 參數範例

```json
{
    "MerchantID": "2000132",
    "RqHeader": {
        "Timestamp": 1234567890
    },
    "Data": "…"
}
```

## Data 參數說明（JSON 格式）

注意事項：加密前需對參數值進行 URLEncode

| 欄位名稱 | 型別 | 長度 | 必填 | 說明 |
|---------|------|------|------|------|
| MerchantID | String | 10 | 是 | 特店編號 |
| RelateNumber | String | 20 | 是 | 廠商自訂編號（唯一值，不可重複；勿使用特殊符號；大小寫英文視為相同） |
| InvoiceTime | String | 20 | 否 | 發票開立時間（格式：yyyy-mm-dd hh:mm:ss）；僅接受過去 6 天內日期；建議不帶值，系統自動開立當下日期 |
| CustomerIdentifier | String | 8 | 是 | 買方統編 |
| CustomerEmail | String | 200 | 否 | 買方電子信箱；僅接受標準 Email 格式；多組以半形分號區隔；測試環境勿帶入真實電子信箱 |
| CustomerAddress | String | 100 | 否 | 買方公司地址 |
| CustomerTelephoneNumber | String | 26 | 否 | 買方電話號碼 |
| ClearanceMark | Number | - | 否 | 通關方式註記；當課稅類別為 2（零稅率）時，帶 1（非經海關出口）或 2（經海關出口） |
| InvType | String | 2 | 是 | 字軌類別；07：一般稅額計算之電子發票；08：特種稅額計算之電子發票 |
| TaxType | String | 1 | 是 | 課稅別；InvType 為 07 時：1（一般應稅）、2（零稅率）、3（免稅）；InvType 為 08 時：3（免稅）、4（特種應稅） |
| TaxRate | Number | - | 否 | 稅率；系統根據課稅類別自動設定（應稅 0.05、零稅率 0、免稅 0） |
| ZeroTaxRateReason | String | 2 | 否 | 零稅率原因；自 2026 年 1 月 1 日起，課稅類別為 2（零稅率）時必填或廠商後台需設定 |
| SpecialTaxType | Number | - | 否 | 特種稅額類別；課稅別為 3（免稅）時必填帶 8；課稅別為 4（特種應稅）時必填帶 1-8 |
| Items | Array[Object] | - | 是 | 商品明細陣列 |
| SalesAmount | Number | - | 是 | 銷售額合計（整數，最多 12 位，不可為 0 元；需等於商品合計加總四捨五入至整數的值） |
| TaxAmount | Number | - | 是 | 稅額合計（整數，最多 11 位；特種稅額發票帶 0） |
| TotalAmount | Number | - | 是 | 發票金額（整數，最多 12 位，不可為 0 元；需等於銷售額合計加稅額合計） |
| InvoiceRemark | String | 200 | 否 | 發票備註 |

| 代碼 | 說明 |
|------|------|
| 71 | 第一款：外銷貨物 |
| 72 | 第二款：與外銷有關之勞務，或在國內提供而在國外使用之勞務 |
| 73 | 第三款：依法設立之免稅商店銷售與過境或出境旅客之貨物 |
| 74 | 第四款：銷售與保稅區營業人供營運之貨物或勞務 |
| 75 | 第五款：國際間之運輸 |
| 76 | 第六款：國際運輸用之船舶、航空器及遠洋漁船 |
| 77 | 第七款：銷售與國際運輸用之船舶、航空器及遠洋漁船所使用之貨物或修繕勞務 |
| 78 | 第八款：保稅區營業人銷售與課稅區營業人未輸往課稅區而直接出口之貨物 |
| 79 | 第九款：保稅區營業人銷售與課稅區營業人存入自由港區事業或海關管理之保稅倉庫、物流中心以供外銷之貨物 |

### SpecialTaxType 列表

| 代碼 | 說明 | 稅率 |
|------|------|------|
| 1 | 酒家及有陪侍服務之茶室、咖啡廳、酒吧 | 25% |
| 2 | 夜總會、有娛樂節目之餐飲店 | 15% |
| 3 | 銀行業、保險業等專屬本業收入 | 2% |

| ItemName | String | 500 | 是 | 商品名稱 |
| ItemCount | Number | - | 是 | 商品數量（支援整數最多 8 位，小數 7 位） |
| ItemWord | String | 6 | 否 | 商品單位 |
| ItemPrice | Number | - | 是 | 商品價格（支援整數最多 10 位，小數 7 位；請填入未稅價） |
| ItemAmount | Number | - | 是 | 商品合計（支援整數最多 12 位，小數 7 位；商品數量×商品價格四捨五入後差距不可大於 1） |

## 綠界 Response 參數說明（JSON 格式）

### 外層參數

| 欄位名稱 | 型別 | 長度 | 說明 |
|---------|------|------|------|
| PlatformID | String | 10 | 特約合作平台商代號 |
| MerchantID | String | 10 | 特店編號 |
| RpHeader | Object | - | 回傳資料 |
| TransCode | Int | - | 回傳代碼；1 代表 API 傳輸資料接收成功，實際執行結果請參考 RtnCode |
| TransMsg | String | 200 | 回傳訊息 |
| Data | String | - | 加密資料（加密過的 JSON 格式） |

### RpHeader 物件

| 欄位名稱 | 型別 | 說明 |
|---------|------|------|
| Timestamp | Number | 回傳時間（Unix timestamp） |

### Response 參數範例（外層）

```json
{
    "MerchantID": "3002607",
    "RpHeader": {
        "Timestamp": 1234564848
    },
    "TransCode": 1,
    "TransMsg": "Success",
    "Data": "…"
}
```

## Data 參數說明（Response JSON 格式）

| 欄位名稱 | 型別 | 長度 | 說明 |
|---------|------|------|------|
| RtnCode | Int | - | 回應代碼；1 為成功，其餘為失敗 |
| RtnMsg | String | 200 | 回應訊息 |
| InvoiceNumber | String | 10 | 發票號碼；開立成功則回傳發票號碼，失敗則回傳空值 |
| RandomNumber | String | 4 | 隨機碼 |

### Data 參數範例（Response）

```json
{
    "RtnCode": 1,
    "RtnMsg": "新增成功",
    "InvoiceNumber": "VG11000002",
    "RandomNumber": "6686"
}
```

## 重要注意事項

1. 開立對象為營業人時，需輸入買方統編，應串接 B2C 電子發票 API，無需特別串接 B2B 電子發票 API。
2. 確認流程，需等待交易相對人（營業人）確認後才完成交換，才屬於有效憑證交換。
3. 時間校正：合作特店須進行主機時間校正，避免主機產生時差，否則 API 無法正常運作。
4. 測試環境規範：測試環境請勿帶入真實電子信箱，避免個資外洩；測試環境僅驗規則，不提供發信測試。
5. Email 格式驗證：採用指定之正規表達式檢核標準格式。
6. 稅額計算誤差：商品合計四捨五入後與商品合計值差距不可大於 1 元；稅額合計與計算值差距不可大於 2 元。
7. RelateNumber 限制：均為唯一值不可重複使用；大小寫英文視為相同。
